# 网页搜索 v2：问题定位与当前验证状态

更新日期：2026-10-02

## 当前判断

最近遇到的现象来自两条不同的链路：搜索服务本身可能没有返回可用网页结果；搜索成功后，本地 Ollama 模型还需要另外处理搜索摘要。网页搜索不会常驻占用模型或显存。应用先向所选搜索 Provider 发送本轮搜索词，再把最多 5 条结果交给本地模型总结。

如果看到 Ollama 请求拒绝或模型没有生成文字，错误发生在模型生成阶段时，网页搜索并没有一直占用模型。过长的聊天上下文、模型的工具调用协议兼容性和模型空回答都可能导致该现象；仅凭聊天气泡无法唯一确定具体原因，需要查看 Ollama 返回的 HTTP 状态与原因。新版会保留近期完整对话轮次，并在 UI 中显示 Ollama 的具体错误，而不再把所有错误都写成“模型离线”。

## 已定位的搜索问题

### 勾选网页搜索却没有发起搜索

旧流程要求本地模型自行决定是否调用联网工具。小型模型可能直接回答，或认为用户没有明确要求联网，因此即使勾选网页搜索也会跳过检索。

当前版本把常见的信息查询、推荐、解释、比较和时效性问题的搜索判断放在应用侧：符合条件时先搜索，再调用本地模型；本地模型不需要自己发起搜索。纯问候和明确的本地文件操作会跳过联网。该判断依赖本地文本规则，少见措辞仍可能未匹配；此时可在问题中加入“请联网搜索”或“查一下最新信息”。

### 搜索服务拒绝或没有结果

- 本机没有 Docker，因此默认的 `http://127.0.0.1:8888` SearXNG 服务没有启动。选择该 Provider 时会得到连接失败提示。团团本身不依赖 Docker 才能启动；可以启动随包提供的 SearXNG，或改用 Chrome / Google、Chrome / Bing，或主动选择 Ollama Web Search API。
- Chrome Provider 使用团团自己的浏览器资料夹。实测 Google 返回了人机验证页面，程序按设计停止，没有尝试绕过。Bing 页面未提取到有效搜索结果；这可能与结果页面布局、地区响应或页面变化有关，目前不能确认其中哪一种是唯一原因。结果解析失败时会停止联网回答，不会把导航栏或广告伪装成结果。
- 不会在以上 Provider 失败后自动回退到 Ollama Web Search API，避免用户不知情地产生 API 用量。切换到该模式或测试连接前，设置界面会提示可能计费。

### 搜索之后本地模型拒绝或没有文字

一次用户消息最多执行一次网页搜索。代码中的最多 4 轮是本地 Agent 的模型/工具交互轮次，不是 4 次网页搜索，也不是联网模块持续占用模型。搜索成功后，模型仍需在当前上下文窗口内读取用户问题和搜索结果；如果对话很长、模型返回不兼容的工具调用或只返回空内容，仍可能产生模型拒绝或无文字提示。开启新聊天或缩短问题可以作为诊断方式，但不是搜索服务故障的修复。

## 建议的下一步验证

1. 在 D 盘目录运行 `Tools\start-searxng.ps1`，等待本机容器就绪，在团团网页搜索设置中测试 SearXNG。
2. 若不安装 Docker，填写可访问的 SearXNG 服务地址，或在独立 Chrome Profile 中手动检查所选搜索引擎页面。
3. 搜索设置测试成功后，新建短聊天，勾选网页搜索，询问一条需要最新信息的问题；确认 UI 显示实际查询词、来源和结果链接，再确认本地模型依据这些结果总结。
4. 若搜索结果已显示但模型拒绝，请记录 Ollama 错误状态和当前上下文长度，以区分模型/上下文问题与搜索 Provider 问题。
