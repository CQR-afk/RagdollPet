# 团团 Agent 下一轮迭代路线

## 目标

本轮只按笔记本配置（32GB 系统内存、8GB RTX 4060 Laptop GPU）筛选模型，验证本地 Agent、工具调用、多模态及 RAM/显存混合加载，再扩展技能系统。保持本地优先、技能按需启用、写入和执行操作可见并逐项确认。本轮不采用另一台 16GB 显存台式机的选型。

## 阶段一：模型与混合加载基准

以当前 `qwen3:4b`（约 2.5GB）和已测的 `qwen3:14b`（Q4_K_M，约 9.3GB）作基线。新的候选按顺序为：

1. **Ornith 1.0 9B Q4_K_M（约 5.63GB）**：优先测试本地 Agent、代码和工具调用；官方 GGUF 仓库提供 Ollama 拉取方式。
2. **Gemma 4 E4B Q4_K_M（Bartowski GGUF 约 5.41GB）**：测试轻量文本与图像理解。官方 Ollama 库的 E4B 文件约 9.6GB；为了遵照本轮选定的笔记本量化档，使用用户提供的 Bartowski 量化 GGUF，并先确认当前 Ollama 后端能正常加载图像输入。
3. **Ornith 1.0 35B Q4_K_M（约 21.2GB）**：作为最后的 MoE/RAM 卸载压力测试，首测使用 4K 上下文并监控可用 RAM、GPU 显存和是否换页。官方模型卡标注 35B-MoE，但未在该卡中明确列出每 token 激活参数数；A3B 标注来自本轮参考材料，不能当作官方卡已确认规格。

14B 结果显示，该笔记本能混合加载超过显存容量的模型，但速度比 4B 慢很多。对以上候选继续让 Ollama 自动分配 CPU/GPU 层，不强制 `num_gpu`；首轮统一用 4K/8K 上下文，不把模型标称最大上下文当作免费的内存占用。

每个模型用同一组任务对比：中文多轮对话、工具选择与参数正确性、文件内容摘要、连续两步工具调用。记录首 token 延迟、生成速度、峰值 GPU 显存和系统内存、工具调用成功率、是否发生换页卡顿。通过 `ollama ps` 记录 Ollama 报告的 CPU/GPU 分配比例；确认实际体验后再决定默认模型，继续保留 4B 作为低资源档。

### 当前初步结果

- 2026-10-02：已下载并测试 `hf.co/ornith-ai/Ornith-1.0-9B-GGUF:Q4_K_M`（约 5.6GB）。8K 上下文、`think=false` 的中文任务输出约 40 token/s；Ollama 报告 100% GPU，GPU 占用约 6.6GB。一次工具调用测试正确生成 `read_clock` 和 `Australia/Sydney` 参数，未执行工具本身。
- 2026-10-02：已下载并测试 `hf.co/bartowski/google_gemma-4-E4B-it-GGUF:Q4_K_M`（权重约 5.4GB，另含约 990MB 视觉组件）。同一类中文任务生成约 53 token/s；Ollama 报告 100% GPU。仓库桌宠图片输入识别结果为“灰白色的猫”，图片测试约 59 token/s；测试时系统可用内存约 16.9GB、GPU 显存占用约 5.8GB。首次请求包含模型加载时间约 41 秒，热运行生成耗时较短。
- 当前 Gemma 测试使用 Bartowski GGUF；官方 Ollama 库的 E4B 包约 9.6GB，和本轮 5.4GB 量化 GGUF 不是同一个包，不能直接比较文件体积。
- 2026-10-02：已下载 `hf.co/ornith-ai/Ornith-1.0-35B-GGUF:Q4_K_M`（约 21GB）到 D 盘并完成 4K 短测。Ollama 报告约 72% CPU / 28% GPU；冷启动并生成 34 token 共约 78 秒，生成速度约 3.0 token/s。运行峰值可用 RAM 约 5.0GB、显存占用约 7.4GB；停止模型后可用 RAM 恢复到约 20.3GB。能混合加载，但速度慢、内存余量小，只适合短时实验，不建议日常常驻。
- 35B 实测到可用 RAM 最低约 5GB，没有触发 4GB 停止线；后续若复测更长任务，应继续观察内存和是否持续换页，不改系统分页文件位置。
- 35B 官方模型卡标注 35B-MoE；当前仅确认 Ollama 可运行该仓库的 Q4_K_M 包，模型卡未明确给出每 token 激活参数数量。
- 2026-10-02：已在本机下载 `qwen3:14b`（Q4_K_M，9.3GB）到 `D:\pet\OllamaModels`。
- 8K 上下文、`think=false` 时，Ollama 报告约 42% CPU / 58% GPU，GPU 显存约 7.3–7.6GB；14B 可以在此机器上混合加载并正常响应。
- 同一条 96 token 输出任务：14B 单次约 4.05 token/s、模型加载约 18 秒，运行中可用系统内存约 15.3GB；4B 单次约 61.32 token/s、模型加载约 8.8 秒，运行中可用系统内存约 19.0GB。两次样本仅作方向判断，仍需多轮复测。
- 当前客户端的普通文字聊天没有显式设置 `think`，语音回复则会对 Qwen 显式关闭思考；下一轮应将思考模式变成可控的模型/任务设置，并测量工具任务成功率与实际响应延迟。
- 工具调用目前仅对 Ornith 9B 做过一次格式验证；连续工具调用成功率和真实桌宠聊天 UI 体验尚未测。轻量版默认模型暂不调整。

`qwen3.8-flash-next` 暂不下载：Ollama 上 Q4_K_M 权重约 120GB，远超当前系统内存与显存预算；激活参数数不能代替需要管理的总权重容量。

## 阶段二：技能注册与权限

当前迭代已为文件搜索和 PDF 读取增加独立开关，并只把启用的技能提供给模型；调用时在聊天中展示目标路径或搜索范围。文件搜索限制在用户指定目录，拒绝符号链接并设定扫描上限；PDF 文本只在本机提取并传给本机 Ollama。写入、删除和 PowerShell 仍逐项确认。按本机基准，9B 使用 8K 上下文，35B 自动限制为 4K，PDF 在 35B 下缩短输入字符上限以留出生成空间。

下一轮优先顺序：

1. **网页搜索与来源摘要（已完成多 Provider 迭代）**：网页搜索开关开启后，应用会在本地模型生成前自动检索普通信息问题、解释、比较和推荐请求；问候语及明确的本地文件操作会跳过搜索。WebSearchManager 支持 SearXNG、团团专用 Chrome（Google/Bing）和 Ollama Web Search API。默认 SearXNG 请求 `127.0.0.1:8888`；官方 Docker 镜像配置启用 JSON 并仅映射本机回环地址，Docker 不存在时不自动安装。Chrome 使用 D 盘发布目录中的独立持久 Profile，不读取日常 Chrome Profile，不绕过验证码。Ollama API Key 继续由 Windows DPAPI 在原文件中加密保存，并且不会作为自动回退。每轮最多检索一次，只发送当前搜索词，不传聊天历史或本地文件；最多 5 条规范化结果随系统消息交给本地模型。搜索失败或无结果时直接结束本轮，结果按不可信资料处理。
- 多轮搜索后的 Ollama HTTP 拒绝可能来自 8K 上下文积累或模型/工具协议兼容性。聊天 API 现在仅发送最近完整轮次（旧记录仍保存在本地），并在非 2xx 响应时显示状态码与 Ollama 原因，避免将请求内容错误地标成“服务离线”。
- 2026-10-02：用户实测发现开启搜索后普通推荐问题仍偶尔未触发；DuckDuckGo HTML 也曾返回验证页。应用自动检索已保留，并增加 SearXNG 与独立 Chrome 搜索，避免绑定 Ollama 的计次服务。当前构建机没有 Docker；SearXNG 启动脚本已随包提供，但本机服务启动及真实结果仍需 Docker Desktop。Chrome 和 Ollama 后端也需按最终构建状态分别执行真实联网验收。Ollama API key 文件、DPAPI 加密方式与原读取兼容。
2. **指定窗口读取**：优先读取用户选择窗口的 Windows UI Automation 控件树；只有控件信息不足且用户要求时，才抓取该窗口并用 OCR/视觉分析。不做隐式全屏监控。
3. **技能状态与工具调用记录**：在聊天 UI 中进一步显示技能启用状态、运行状态及精简结果，并可为后续提醒/日历等技能复用相同注册机制。

## 阶段三：视觉模型与应用操作

Ornith 9B 是当前 Agent 主要实验模型，Gemma 4 E4B 经本机图片输入验证后作为视觉任务候选；35B 仅短时混合加载测试。窗口读取先用 UI Automation/OCR 做结构化输入；图片理解再调用支持视觉的 E4B。应用操作从只读控件发现开始，点击、输入、发送等动作需显示目标控件并确认。

## 完成标准

- 网页搜索默认关闭；开启后普通信息问题、解释和推荐会自动搜索；用户能查看实际查询词及结果来源；搜索请求不包含聊天历史或本地文件。搜索失败时本轮停止生成。

- 用户能在 4B 与更大模型间切换，且 4B 低资源选项保持可用；完整版优先选择 Ornith 9B。
- 9B、E4B 与 35B 的 GPU/RAM 分配、速度和对应能力有同机记录；35B 仅作实验档。
- 已交付目录内文件搜索和 PDF 文本提取两项可单独启停的技能；下一轮优先交付联网搜索与来源摘要，然后补齐指定窗口读取。
- 技能权限在界面中可见；读取范围受限，写入、删除、命令和应用副作用有明确确认。
